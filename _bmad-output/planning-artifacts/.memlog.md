- (decision) Heddle is an independent open-source project owned by Cédric Thedrez (kamicoder), with no organizational affiliation.
- (decision) Heddle is one local-first cross-platform product and modular monorepo, structured as a modular monolith with supervised optional sidecars and workers.
- (decision) The headless core API is authoritative, the CLI exposes every capability, and graphical interfaces remain overlays.
- (decision) Heddle owns the Rust control plane, canonical state, policy, workflows, context, evidence, and completion decisions.
- (decision) External agents are replaceable bounded WorkerAdapters or reuse sources and never become Heddle's source of truth.
- (decision) Architecture follows hexagonal ports and adapters with event-sourced canonical execution state.
- (decision) Local, Online-Server, and Online-Remote modes use sealed silos with no cross-mode session or information sharing.
- (decision) Remote sharing is restricted to authorized members of the same team.
- (decision) The local backend always exists; its network exposure is configurable and local execution stands down while attached to another Heddle instance.
- (decision) Mode changes are detected and proposed rather than imposed, require user choice, and never migrate session data automatically.
- (decision) Configuration resolves through Silo, Team, Project, and Conversation; explicit higher locks cap lower scopes and security may only tighten.
- (decision) Authorization is deny-by-default and must combine scoped RBAC, ABAC, ReBAC, risk, ownership, and auditable obligations.
- (decision) MCP connectors are local-only or disabled by default and require authorization from the applicable hierarchical scope owner.
- (decision) Computer access defaults to project scope and may be widened explicitly to a folder or selected computer capabilities.
- (decision) Local mode enforces no egress at a hard network boundary; all network-capable adapters are classified and other modes remain allowlist-based.
- (decision) Secrets remain references, are resolved just in time, and must not enter model context, logs, telemetry, or persistent configuration.
- (decision) The Ledger records model I/O, tools, state, policy, budgets, and evidence as append-only hash-chained events correlated with a separate audit journal.
- (decision) Replay uses recorded results by default; external effects require intent and outcome records, idempotency, authorization, and explicit re-execution.
- (decision) Loops have mandatory engine-enforced budgets, no-progress detection, external ground-truth verification, three-level checks, and human escalation.
- (decision) Every model call uses a reproducible ContextManifest and smallest-sufficient context selection.
- (decision) Million-token windows are overflow capacity, not normal working memory; the repository may exceed one million tokens.
- (decision) Repository maps, symbol and dependency indexes, hybrid retrieval, lazy loading, and traceable trajectory compression are core capabilities.
- (decision) Heddle presents an omni experience by orchestrating multiple specialized models and tools sequentially or in parallel.
- (decision) BMAD governs product planning and readiness while Spec-Kit executes each feature through clarification, planning, tasks, checklists, analysis, and implementation gates.
- (decision) One-way-door decisions must be resolved before code; reversible details are specified per current slice and deferred behind explicit triggers.
- (decision) Commodity infrastructure is reused behind Heddle-owned replaceable contracts instead of being wholesale reimplemented.
- (change) The opaque Goose CLI runtime plan is superseded because it cannot provide governed per-turn events, exact Ledger capture, or enforced termination.
- (change) Goose-first Phase 0 plans and tasks are stale and must be regenerated after runtime and worker evidence spikes.
- (change) Content hashes as Ledger primary keys are superseded by surrogate event identifiers with separate integrity hashes and causal sequencing.
- (override) Universal reversibility is replaced by replayable history and explicit pure, reversible, compensatable, irreversible, and unknown effect semantics.
- (override) Universal provider, compliance, transparency, and framework-mastery claims are replaced by tested capability contracts and compliance-support controls.
- (assumption) Ollama is the current default local-inference candidate, pending cross-platform packaging and capability evidence.
- (assumption) LiteLLM is an initial replaceable gateway adapter and does not define Heddle's capability or policy model.
- (assumption) Rust control, TypeScript UI, and optional Python specialization are the leading stack hypothesis pending integration and packaging spikes.
